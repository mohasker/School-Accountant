# تشغيل وأمان

## نموذج الحماية

جلسة خادمية عشوائية 256-bit، لا JWT للتجديد، ولا رموز في localStorage. يُخزن hash رمز الجلسة فقط. cookie من نوع HttpOnly/SameSite=Strict وSecure في الإنتاج. الخروج يحذف الجلسة في الخادم؛ تغيير كلمة المرور يلغي كل الجلسات. انتهاء مطلق 8 ساعات وخمول 30 دقيقة.

طلبات التعديل تتطلب CSRF وتفويضاً حسب المدرسة. كل بند وتكليف وعام ومورد مرتبط بقيود مركبة تمنع خلط النطاقات. الإدارة التقنية ليست اعتماداً مالياً تلقائياً. يُمنع مُعد المعاملة من اعتمادها ومُحمّل الملف من التحقق منه.

المبالغ Decimal ثابتة الدقة والتقريب HALF_UP، والتحويل من الارتباط إلى المصروف ذري. مفتاح idempotency مطلوب للتعديل. يتحقق الخادم من الكميات والمدفوعات؛ لا يُعتمد على الواجهة للحساب.

## تخزين

الملفات المؤيدة في PostgreSQL bytea، والمستندات المولدة snapshots/HTML خاصة؛ لا ملفات حساسة في public. هذا مناسب للتجربة؛ راجع السعة والتشفير وسياسة الاحتفاظ قبل الإنتاج. نسخ SQL العادية لا تحمي من مدير قاعدة ذي صلاحية فائقة؛ يلزم فصل صلاحيات وحفظ سجلات خارجي.

## النسخ الاحتياطي المقترح مع Docker

```bash
docker compose exec -T db pg_dump -U school -Fc school_accounting > school-accounting.backup
```

يحتوي النسخ على بيانات حساسة، خزنه مشفراً خارج الجهاز وفق سياسة الجهة. اختبر الاستعادة في قاعدة جديدة منفصلة، وليس فوق الأصل:

```bash
pg_restore --dbname=CONNECTION_TO_NEW_EMPTY_RESTORE_DATABASE school-accounting.backup
```

قارن أرصدة Budget بمجموع Ledger، والكمية المقبولة والمعتمدة، وبصمات الملفات والتقارير، والصلاحيات بعد الاستعادة. سجّل زمن الاستعادة ونقطة البيانات، وحدد RPO/RTO مع المؤسسة.

لا تستخدم docker compose down -v إلا إذا كان حذف بيانات التجربة مقصوداً وموافقاً عليه؛ الخيار -v يحذف وحدة بيانات قاعدة البيانات.

## الترقية

خذ نسخة احتياطية واختبر الترحيل على نسخة معزولة. لا تعدل ملف migration مُطبق؛ أضف ترحيلاً جديداً. لا تعكس مخططاً بعد تسجيل معاملات جديدة دون خطة توافق وتسوية. تحديث Prisma 6 إلى إصدار مدعوم أطول أجلاً مطلوب ضمن مراجعة الاعتماديات قبل الإنتاج.
