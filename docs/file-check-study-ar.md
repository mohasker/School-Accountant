# دراسة فنية: فحص المعاملة الورقية قبل الإرسال

الإصدار: 2026-10-01.7 — الحالة: منفّذ ومختبر (65 اختباراً آلياً ناجحاً)، والقراءة الآلية الحقيقية تحتاج تجربة بملفات فعلية.

## 1. الهدف

بعد طباعة مستندات المعاملة وتوقيعها وختمها، وقبل إرسالها، يرفع المحاسب الملف الورقي كاملاً (PDF ممسوح أو صور بالموبايل) على النظام أو عبر بوت تليجرام. النظام يقرأ كل ورقة، ويقارنها بما هو مسجل للمعاملة نفسها، ويصدر **تقريراً من صفحة A4 واحدة** فيه:

- **أخطاء تمنع الإرسال** (أحمر)
- **تنبيهات تحتاج قراراً** (أصفر)
- **ملاحظات** (رمادي)
- **قائمة مراجعة يدوية** لما لا يمكن رؤيته آلياً.

الفحص **لا يغيّر أي شيء في المعاملة**؛ يُحفظ كسجل مستقل مع التقرير ويُكتب في سجل التدقيق.

## 2. ما يُراجَع

| البند | ما يُفحص |
|---|---|
| **اسم المدرسة** | يظهر في كل ورقة، وبنفس الصيغة المسجلة. اسم مدرسة أخرى من مدارس النظام خطأ. اختلاف إملائي تنبيه. |
| **تسلسل التواريخ** | عرض السعر ← تقرير العروض ← كتاب التكليف ← الفاتورة وسند الاستلام ← شهادة الإنجاز ← كتاب التغطية. لا تاريخ مستقبلي، والتواريخ داخل العام المالي. |
| **تطابق التواريخ** | تاريخ كل مستند صادر من النظام على الورق = المسجل (التقرير، التكليف، الشهادة، التغطية، الاستلام). |
| **الأرقام المرجعية** | رقم التكليف على التكليف والشهادة والفاتورة = المسجل. رقم الفاتورة مسجل في المعاملة. لا فاتورة واحدة بقيمتين. مرجع كل عرض وارد في التقرير. |
| **المبالغ** | قيمة التكليف. الفاتورة لا تتجاوز التكليف. المستحق والغرامة والصافي في الشهادة = المسجل، والصافي = المستحق − الغرامة. صافي كتاب التغطية. إجمالي كل عرض. |
| **الغرامة على الورق** | إذا كان تاريخ الاستلام على الورق بعد آخر موعد والشهادة بلا غرامة = خطأ. |
| **التوقيعات والأختام** | كل خانة توقيع على التقرير والتكليف والشهادة والتغطية موقّعة. سند الاستلام موقّع من المستلم. الفاتورة عليها ختم أو توقيع المورد. ختم المدرسة على التكليف والشهادة والتغطية. |
| **الاكتمال** | المستندات المطلوبة في مرحلة المعاملة موجودة: تقرير العروض، التكليف، الفاتورة، سند الاستلام، الشهادة، التغطية. عدد عروض الأسعار المرفقة. |
| **اسم المورد** | نفس مورد المعاملة في التكليف والفاتورة والشهادة والتغطية (يقبل الاسم القانوني والاسم الإنجليزي من بنك الموردين). |
| **متطلبات الإدارة** | قائمة يكتبها مدير النظام (مثل «الفاتورة إلكترونية وعليها رمز QR»)؛ لكل متطلب مستوى خطأ أو تنبيه. |
| **الوضوح** | صفحة غير واضحة = تنبيه بإعادة التصوير. |

## 3. المدخلات

| المدخل | الطريقة | الحدود |
|---|---|---|
| **شاشة المعاملة** | لوحة «فحص الملف قبل الإرسال» أسفل صفحة المعاملة؛ اختيار عدة ملفات PDF أو صور بالترتيب ثم «فحص الملف». | الصور تُصغَّر في المتصفح إلى 2000 بكسل JPEG قبل الإرسال. حتى 15 ملفاً و25 ميجابايت و40 صفحة. |
| **بوت تليجرام** | «فحص TR-00012» ثم إرسال الصور أو ملفات PDF ثم «تم»؛ يصل ملخص بأهم الأخطاء وملف التقرير PDF. | نفس الحدود. يُفضّل إرسال الصور «كملف» للحفاظ على الدقة. تنتهي جلسة التجميع بعد 30 دقيقة. |

الفحص متاح بعد إصدار تقرير العروض أو كتاب التكليف، ولأصحاب الصلاحية في مدرسة المعاملة فقط.

## 4. مشكلة القراءة ونتيجة التجربة

قبل التصميم جُرّبت قراءة ملف PDF مطبوع من النظام نفسه:

- **الأرقام والتواريخ والمراجع اللاتينية** (مثل `03/09/2026` و`ABAF/2026/007`) تُقرأ من نص الملف **بدقة كاملة**.
- **الكلمات العربية** تخرج حروفاً منفصلة ورموزاً مكسورة بسبب طريقة تضمين الخط، فلا يمكن الاعتماد عليها لمقارنة الأسماء.
- **الملف الموقّع الممسوح أو المصوّر** (وهو الحالة الفعلية بعد التوقيع والختم) **ليس فيه نص أصلاً**.

لذلك يوجد مساران، يختار مدير النظام بينهما:

| | **القراءة الآلية (AI)** | **نص PDF فقط (افتراضي)** |
|---|---|---|
| ما يُقرأ | كل صفحة: نوع المستند، اسم المدرسة والمورد، التواريخ، الأرقام، المبالغ، التوقيعات، الختم، الوضوح، متطلبات الإدارة | الأرقام والتواريخ والمراجع من ملفات PDF الرقمية فقط |
| الصور والمسح الضوئي | تُقرأ | لا تُقرأ؛ تظهر كتنبيه |
| خروج البيانات من الخادم | الملف يُرسل إلى خدمة Anthropic | لا شيء يخرج |
| الأسماء والتوقيعات والأختام | تُفحص آلياً | قائمة مراجعة يدوية في التقرير |
| التكلفة | تقريباً 0.15–0.30 دولار لملف من 10 صفحات (تقديري) | بلا تكلفة |

## 5. التصميم

```
الشاشة / تليجرام
      │  الملفات (PDF / JPG / PNG)
      ▼
فحص النوع والحجم ومضاد الفيروسات (نفس فحص المرفقات)
      │
      ├── القراءة الآلية مفعّلة ← Claude يقرأ الصفحات «بلا معرفة بالمسجل»
      └── غير مفعّلة         ← نص PDF: تواريخ، مراجع، مبالغ
      │
      ▼  حقائق كل صفحة
القواعد الثابتة (core/file-check/rules.ts) ← بيانات المعاملة من قاعدة البيانات
      │
      ▼  أخطاء / تنبيهات / ملاحظات + قائمة يدوية
تقرير A4 واحد + حفظ الفحص + سجل التدقيق
```

**مبادئ أساسية:**

1. **القراءة عمياء**: خدمة القراءة لا تُعطى أي قيمة مسجلة (لا رقم التكليف ولا اسم المدرسة ولا المبالغ)، فلا يمكن أن «تؤكد» ما تتوقعه. الاختبار الآلي يتحقق من أن الطلب المرسل لا يحتوي هذه القيم.
2. **الحكم بقواعد ثابتة**: المقارنة والتصنيف والنتيجة كلها كود ثابت. نفس الملف يعطي نفس النتيجة دائماً، والخدمة الخارجية لا تقرر شيئاً.
3. **لا افتراض**: الحقل غير المقروء يرجع فارغاً ويُعامل كـ«غير ظاهر»، لا كقيمة صحيحة.
4. **مقارنة الأسماء بعد التوحيد**: تُهمل التشكيل والتطويل، وتُوحَّد (أ إ آ ← ا، ة ← ه، ى ← ي) والمسافات وكلمة «مدرسة». بعدها: مطابق، أو اختلاف بسيط (تنبيه)، أو مختلف (خطأ). مطابقة اسم مدرسة أخرى في النظام خطأ دائماً.
5. **الأرقام**: الأرقام العربية الهندية تُحوَّل، والمسافات تُحذف، والمبالغ تُقارن لأقرب درهم.

### ما يُحفظ

لكل فحص: المصدر (شاشة / تليجرام)، طريقة القراءة، أسماء الملفات وأحجامها و**بصمة SHA-256** لكل ملف، الحقائق المقروءة لكل صفحة، الملاحظات، النتيجة، التقرير، ومن فحص ومتى. **الملف نفسه لا يُخزَّن**؛ من يريد الاحتفاظ بالنسخة الموقّعة يرفعها في «المرفقات». البصمة تثبت أي ملف فُحص بالضبط.

## 6. الأمان والخصوصية

- **القراءة الآلية معطلة افتراضياً**؛ يفعّلها مدير النظام صراحة من «السياسة المالية ← فحص المعاملات»، وتُستخدم نفس مفتاح المساعد الذكي.
- بدونها لا يخرج أي ملف من الخادم.
- الملفات تمر بنفس فحص النوع ومضاد الفيروسات المطبق على المرفقات.
- الفحص لأصحاب صلاحية العمل في مدرسة المعاملة؛ المدقق يقرأ التقارير ولا يشغّل فحصاً.
- حد 20 فحصاً في الساعة لكل مستخدم (يحمي التكلفة وسوء الاستخدام).
- البوت يعمل في الدردشات الخاصة فقط وللحساب المرتبط فقط، وبنفس صلاحياته.
- كل فحص في سجل التدقيق مع بصمات الملفات.

## 7. التقرير

ورقة A4 واحدة بترويسة الوزارة: المدرسة، رقم المعاملة، المورد، رقم التكليف، القيمة، عدد الصفحات، طريقة القراءة والمصدر، ثم شريط النتيجة (جاهز للإرسال / جاهز بعد مراجعة التنبيهات / يحتاج تصحيحاً)، ثم الأقسام الثلاثة مرتبة بالصفحة، ثم قائمة المراجعة اليدوية بمربعات للتعليم، ثم سطر من فحص ومتى. إذا زادت البنود عن مساحة الصفحة تُذكر «و N بنداً آخر محفوظة في النظام». الاختبار الآلي يتحقق أن ملف PDF الناتج صفحة واحدة.

## 8. إصلاح مرتبط في النظام نفسه

أثناء الاختبار ظهر أن النظام كان يسمح بإصدار كتاب تكليف بتاريخ **قبل** تاريخ تقرير عروض الأسعار، فيطبع ملفاً يرفضه الفحص نفسه. أُضيف منع ذلك عند الإصدار: «تاريخ كتاب التكليف قبل تاريخ تقرير عروض الأسعار؛ صحّح أحد التاريخين».

## 9. القيود المعروفة

- **دقة القراءة الآلية تعتمد على وضوح الصورة**: الإضاءة، الميل، الظل، والخط اليدوي. لذلك كل قيمة مذكورة في التقرير يجب مقارنتها بالورقة الأصلية قبل التصحيح، والصفحات غير الواضحة تظهر كتنبيه.
- **«موقّع» تعني وجود توقيع**، لا التحقق من صاحبه.
- **مطابقة أصناف الفاتورة بنداً بنداً** مع أصناف التكليف ليست في هذا الإصدار؛ تُفحص القيمة الإجمالية فقط.
- **التفقيط** (المبلغ بالحروف) لا يُقارن في هذا الإصدار.
- **الخدمة الحقيقية لم تُجرّب** في بيئة التطوير (لا يوجد اتصال بها)؛ الاختبارات تستخدم خادماً تجريبياً يرد بنفس الشكل. أول ملفات حقيقية يجب مراجعة نتيجتها يدوياً.
- متطلبات الإدارة في وضع القراءة الآلية تُقيَّم بواسطة الخدمة، لذلك «غير مستوفى» خطأ أو تنبيه حسب ما حدده المدير، و«تعذر التحقق» تنبيه للمراجعة اليدوية دائماً.

## 10. الاختبارات

| الاختبار | ما يثبته |
|---|---|
| FILE CHECK (text) | مستندات النظام المطبوعة نفسها تمر بلا أخطاء؛ تغيير رقم التكليف في ورقة واحدة يعطي خطأ؛ ملف ليس PDF يُرفض؛ محاسب مدرسة أخرى ممنوع؛ التقرير صفحة واحدة؛ سجل التدقيق؛ المعاملة لا تتغير |
| FILE CHECK (AI) | ملف سليم = «جاهز للإرسال»؛ الطلب للخدمة لا يحمل القيم المسجلة؛ ملف معيب يعطي كل نوع: مدرسة أخرى، اختلاف إملائي، قيمة تكليف، فاتورة غير مسجلة، فاتورة قبل التكليف، تغطية قبل الشهادة، تاريخ شهادة مختلف، سند غير موقّع، فاتورة بلا ختم، صافٍ مختلف، متطلب إدارة، صفحة غير واضحة؛ نقص سند الاستلام والتغطية |
| FILE CHECK (Telegram) | «فحص» ثم ملفات ثم «تم» يشغّل نفس الفحص ويرسل الملخص والتقرير PDF؛ نوع ملف غير مدعوم يُرفض؛ ملف بدون «فحص» يعطي التعليمات |

## 11. التجربة المقترحة قبل الاعتماد

1. ابدأ بوضع **نص PDF فقط** على 3 معاملات: ارفع مستندات النظام المطبوعة كما هي، وتأكد من «لا أخطاء».
2. فعّل **القراءة الآلية** (بعد قرار الإدارة بشأن إرسال الصور للخدمة) وجرّب 5 معاملات حقيقية موقّعة ومختومة، منها واحدة فيها خطأ متعمد (تاريخ أو رقم فاتورة).
3. قارن كل بند في التقرير بالورق، وسجّل أي قراءة خاطئة (رقم، تاريخ، توقيع).
4. جرّب نفس الملف من تليجرام بالصور العادية وبالصور «كملف» وقارن الدقة.
5. اكتب متطلبات الإدارة الحالية في الإعدادات، وجرّب ملفاً لا يستوفيها.

## 12. التطوير التالي المقترح

- مطابقة أصناف الفاتورة وكمياتها مع التكليف وسند الاستلام.
- مقارنة التفقيط بالرقم.
- حفظ الملف الممسوح مع الفحص اختيارياً (أو في OneDrive).
- خيار لمدير النظام: منع «إكمال المعاملة» إذا كان آخر فحص فيه أخطاء.
- فحص كشوف تسوية العهد وفواتيرها بنفس الطريقة.
