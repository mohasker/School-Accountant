## 2) المشروع باختصار

- **الغرض**: نظام محاسبي لمحاسب مدارس وزارة التربية والتعليم والتعليم العالي في قطر (MOEHE): يدير المعاملات (الشراء المباشر)، العهد والنثرية، الموازنة وبنودها، شهادات الإنجاز، التقارير، الأرشيف، ويخدم **عدة مدارس لكل محاسب**، و**مراقباً مالياً** يتابع عشرات المدارس، و**مدير نظام**.
- **الاسم**: MOESAS — «نظام محاسبي المدارس الحكومية». (كان سابقاً «Madar»؛ ملفات التشغيل ما زالت `Start-Madar.bat` ولا يُغيَّر اسمها).
- **صاحب المشروع**: محاسب مدارس حكومية؛ يكتب بالعامية المصرية، ويريد الرد بها. ليس مبرمجاً: الشرح يكون خطوة بخطوة بلا مصطلحات غير لازمة.

### دورة المعاملة (أربعة مستندات)
1. **تقرير عروض الأسعار**: الموضوع، بند الموازنة، الشركات وأسعارها — **بالأصناف** (الصنف، الوحدة، الكمية، سعر الوحدة لكل شركة). يُرسى على الأقل سعراً.
   - حتى 1000 ر.ق عرض واحد يكفي؛ فوقها 3 عروض أو مبرر احتكار؛ فوق 200,000 من اختصاص إدارة المشتريات.
   - أو «تكليف وارد من الوزارة» بمرجعه.
2. **كتاب التكليف**: التاريخ ومدة التنفيذ بأيام العمل (تُستبعد الجمعة والسبت والإجازات). الرقم `رمز المدرسة/السنة/تسلسل` مثل `ABAF/2026/007`. يحجز المبلغ من البند.
3. **الاستلام** (جزئي أو كامل) ثم **شهادة الإنجاز**: تاريخ الإنجاز، الفاتورة، الغرامة تلقائياً عند التأخير.
4. **كتاب التغطية** للجهة المرسل إليها (الشؤون المالية / الخدمات العامة / المشتريات…). ثم تسجيل رقم قيد **ERP**.

وأيضاً: **فحص الملف قبل الإرسال** (قواعد ثابتة + قراءة آلية اختيارية)، الملف المجمّع، المرتجعات وملاحظات المدقق، الاعتماد من شخص ثانٍ (اختياري).

### العهد
نثرية / يوم التعليم / معرض الكتاب / خاصة. لا تُسجَّل الفواتير مسبقاً: عند **التسوية** تُدخل كل الفواتير مرة واحدة ثم «تسوية واستعاضة» (النثرية بعد 75%) أو «تسوية وإغلاق». يصدر **كشف التسوية** و**كتاب التغطية**. فاتورة النثرية حتى 1000 ر.ق.

### الأدوار
- **ACCOUNTANT** محاسب المدرسة، **ADMIN** مدير النظام (يتحكم في كل شيء، يحدد مدارس كل محاسب ومراقب من «دليل المدارس»)، **AUDITOR** مدقق للقراءة، **SUPERVISOR** المراقب المالي (قراءة فقط، لوحة مجمعة حسب المحاسب).
- العضوية لها `active`: المدرسة التي انتقلت لمحاسب آخر تبقى عند السابق «غير فعالة» للاطلاع.

## 3) التقنية والبنية

| الجزء | التقنية | المكان |
|---|---|---|
| الخادم (API) | NestJS + Prisma 6.19 + zod | `apps/api/src` |
| الواجهة | Next.js 16 (React) | `apps/web` (الشاشات في `views/`) |
| قاعدة البيانات | PostgreSQL للإنتاج؛ **PGlite** محلياً وفي الاختبارات | `prisma/schema.prisma` + `prisma/migrations` |
| الطباعة / PDF | HTML ← Chromium (playwright-core) | `apps/api/src/print/*`, `core/pdf.ts` |
| Excel | exceljs | الاستيراد والتقارير |
| الاختبارات | node test runner عبر HTTP فعلي | `tests/system.test.ts` (81 اختباراً) |

أهم الملفات:
- `apps/api/src/core/transaction.ts` — `transact()`: معاملة Serializable مع مفتاح تكرار (Idempotency-Key) وإعادة محاولة حتى 12 مرة ثم 409. **داخل المعاملة استخدم `t` وليس `db` أبداً** (الاختبارات تعمل باتصال واحد؛ استخدام `db` يسبب P2028).
- `core/identity.ts` — الدخول، حد المحاولات (الفاشلة فقط)، الجلسات، CSRF. حساب «زائر» المشترك محدود بالعنوان فقط في التجربة.
- `http/controllers.ts` — المسارات العامة (auth…)؛ `modules/router.ts` بقية الوحدات.
- `main.ts` — `originAllowed()`: `WEB_ORIGIN` + `WEB_ORIGINS` + روابط التجربة المؤقتة (trycloudflare / app.github.dev) فقط مع `TRIAL_LINKS=1`.
- `core/principal.ts` — سجل مديري المدرسة بتاريخ البداية (كل مستند باسم المدير في تاريخه).
- `print/layout.ts` — `printDocument({official})`: النماذج الرسمية بلا علامة مائية ولا تذييل.
- `modules/directory.ts` + `scripts/schools-directory.json` — دليل الوزارة (303 مدرسة) وتعيين المحاسب/المراقب.
- `modules/notepad.ts` — «ملاحظاتي» والقيود الاسترشادية.
- `modules/supervision.ts` — لوحة المراقب المالي.
- `modules/backups.ts` + `scripts/local-backups.ts` — النسخ الاحتياطية والاستعادة.
- `scripts/local.ts` — `runLocal(demo)`: يشغّل PGlite + خادم socket على 55432 + الـ API داخل نفس العملية + Next على 3000. ينشئ حساب «زائر» في التجربة (`ensureTrialGuest`).
- `scripts/seed.ts`, `demo-scenario.ts`, `history-data.json`, `legacy-certificates.json` — بيانات التجربة (من ملفات التكليف المعتمدة، مع سنوات 2022–2026).
- `scripts/seed-people.local.json` — **أسماء الأشخاص الحقيقيين (غير مرفوع على GitHub، في .gitignore)**. نسخة منه داخل ملف ZIP الإصدار 0.2.0 (`Madar-V0/scripts/`). بدونه تظهر المسميات الوظيفية بدل الأسماء.

### أوامر التطوير
```bash
npm ci && npx prisma generate
npx tsc --noEmit -p apps/api/tsconfig.json      # فحص الأنواع (API)
npx tsc --noEmit -p apps/web/tsconfig.json      # فحص الأنواع (الواجهة)
npm test                                        # 81 اختباراً (~2 دقيقة)
node --import tsx --test --test-name-pattern="اسم" tests/system.test.ts   # اختبار واحد
npm run build
DEMO_PASSWORD=Madar-Trial-2026 npm run demo     # التجربة على http://localhost:3000 (البيانات في .data/demo)
npx prettier --write <files>
```
بعد `npm run build` أرجِع الملفات التي يعدّلها البناء قبل أي commit:
```bash
git checkout apps/web/tsconfig.json apps/web/tsconfig.tsbuildinfo apps/api/tsconfig.json apps/web/next-env.d.ts
```

## 7) أين توقفنا (المهام المفتوحة)

**آخر نقاش (29 أكتوبر 2026)**: التجربة العملية ستطول. صاحب المشروع ليس لديه Mac mini ولا دومين حالياً، وسيشتري دوميناً.
- البدائل التي نوقشت: Railway (مدفوع، الأسهل)، **Hostinger VPS KVM 2** (مدفوع، حسابه موجود عندهم — **الترشيح الحالي**)، Oracle Always Free (مجاني، تسجيل قد يتعثر)، Codespaces (لا يصلح لتجربة طويلة)، الاستضافة المشتركة في هوستينجر لا تصلح (VPS فقط).
- الخطوات لـ Hostinger VPS: `docs/trial-server-ar.md` (قسم Hostinger). لـ Railway: `docs/railway-ar.md`.
- لم يؤكد صاحب المشروع الاختيار النهائي بعد؛ اسأله أولاً ماذا اشترى.

إن اختار Railway، المطلوب منه (بالترتيب):
1. إنشاء المشروع على Railway من المستودع والفرع `claude/vibrant-bell-tj6ext`.
2. المتغيرات: `DEMO_PASSWORD` (12+ حرفاً)، `RAILWAY_RUN_UID=0`، `WITH_CLAMAV=false`.
3. **Volume** على المسار `/app/.data` (بدونه تُمسح البيانات).
4. Generate Domain على المنفذ **3000**؛ اختيارياً دومين خاص + `WEB_ORIGINS=https://trial.الدومين`.
5. الدخول بـ «زائر / 112233» وتعميم الرابط مع الرسالة في `docs/practical-trial-ar.md`.

ما يجب على الجلسة القادمة التحقق منه / إكماله:
- [ ] متابعة صاحب المشروع خطوة بخطوة في Railway حتى يعمل الرابط (طلب صور الشاشة عند أي خطأ؛ سجل البناء في Deployments ← Logs).
- [ ] **التحقق من طباعة PDF على Railway** (لم يُختبر Chromium داخل Docker في بيئة التطوير لأن مستودعات Debian كانت محجوبة هناك).
- [ ] `deploy/install.sh` (النشر الرسمي) ما زال افتراضياً على فرع `main` القديم — يُصحح إلى `claude/vibrant-bell-tj6ext` عند مرحلة النشر الرسمي.
- [ ] تذكير: إنشاء Release يدوياً على GitHub (Tag `v0.2.2`)، وجعل المستودع **Private** (Railway يعمل مع Private بعد السماح له بالوصول).
- [ ] بعد تشغيل السيرفر: `TARGET=https://الرابط node scripts/load-test.mjs 20 60` ومقارنة النتائج بـ `docs/performance-ar.md`.
- [ ] **n8n (طلب جديد، لم يُنفذ)**: صاحب المشروع سيشغّل n8n للنظام ولأعمال شركته وإشعارات واتساب وأتمتة متعددة. المقترح المعروض عليه (ينتظر موافقته وقائمة الإشعارات المطلوبة):
  1. **مفاتيح ربط (API keys)** يصدرها مدير النظام لكل تكامل، بصلاحيات محددة (قراءة فقط افتراضياً، لمدارس محددة)، قابلة للإلغاء، ومسجلة في سجل التدقيق.
  2. **Webhooks صادرة** من النظام إلى n8n بتوقيع HMAC عند أحداث (معاملة متأخرة، شهادة صدرت، تنبيه موازنة، عهدة بلغت 75%، الملخص الصباحي).
  3. واتساب عبر **WhatsApp Business Cloud API الرسمي** (Meta) من n8n، لا عبر حلول غير رسمية (خطر حظر الرقم). الرسائل بلا تفاصيل مالية حساسة.
  4. فصل بيانات الشركة عن بيانات المدارس (workflows وبيانات اعتماد منفصلة).
- [ ] جمع ملاحظات المجرّبين وتحويلها لإصدارات 0.2.x / 0.3.0.
- [ ] لاحقاً: النشر الرسمي على خادم داخل قطر (Azure Qatar Central أو خادم الوزارة) بعد موافقة إدارة تقنية المعلومات — البيانات الحقيقية لا توضع على Railway أو سيرفرات خارج قطر قبل الموافقة.
