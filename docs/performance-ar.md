# اختبار الأداء (الضغط)

`scripts/load-test.mjs` يحاكي مجرّبين يدخلون بحساب «زائر» ويتنقلون بين الشاشات الرئيسية (اختيار مدرسة، الرئيسية، المعاملات، العهد، وكتابة ملاحظة أحياناً) عبر نفس الطريق الذي يستخدمه المتصفح، وكل مستخدم يقرأ الشاشة 1–3 ثوانٍ قبل الانتقال.

```bash
node scripts/load-test.mjs 20 60                                   # 20 مستخدماً لمدة 60 ثانية على الجهاز
TARGET=https://trial.example.com node scripts/load-test.mjs 20 60  # على السيرفر
```

## النتائج — 29 أكتوبر 2026، نسخة التجربة (PGlite)، جهاز 4 معالجات

| مستخدمون في نفس اللحظة | طلبات/ثانية | زمن الشاشة (المتوسط) | أبطأ 5% | الدخول | أخطاء |
|---|---|---|---|---|---|
| 5 | 10.6 | 25–50 ms | ≤ 0.2 ث | 0.8 ث | 0 |
| 20 | 35 | 50–90 ms | ≤ 0.3 ث | 1.8 ث | 0 |
| 50 | 46 | 0.4–0.9 ث | ≤ 1.2 ث | 3.2 ث | 0 |
| 100 | 46 | 0.9–2.4 ث | ≤ 2.8 ث | 6.2 ث | 0 |

## القراءة
- **حتى 20 مستخدماً نشطاً في نفس اللحظة: سريع جداً** (أقل من ثلث ثانية). 50: مقبول (حوالي ثانية). 100: بطيء (2–3 ثوانٍ) لكن بلا أخطاء.
- المستخدم في الاختبار يفتح شاشة كل 1–3 ثوانٍ؛ المستخدم الحقيقي كل 10–30 ثانية، فـ 20 مستخدماً في الاختبار تقارب **100+ مجرّب حقيقي** يعملون معاً.
- الحد الأعلى (~46 طلباً/ثانية) سببه أن نسخة التجربة تعمل بقاعدة بيانات داخلية باتصال واحد. **النسخة الرسمية** (PostgreSQL بعدة اتصالات، `deploy/install.sh`) لا تحمل هذا القيد.
- الدخول أبطأ عمداً (تشفير كلمة المرور Argon2) ويحدث مرة واحدة لكل جلسة.
- لم يُقس هنا: طباعة PDF تحت الضغط، ورفع الملفات الكبيرة.
