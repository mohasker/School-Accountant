# دليل البدء: التشغيل ثم النشر ثم الاستخدام — MOESAS V0

الأسرع للتجربة: **GitHub Codespaces** (القسم التالي). والخطة الكاملة على ثلاث مراحل:

| المرحلة | أين | المدة المقترحة | الهدف |
|---|---|---|---|
| 1. تشغيل محلي | جهازك | من اليوم الأول | العمل الفعلي على جهازك ببياناتك (نسخة عادية) |
| 2. النشر | خادم سحابي + دومين | نصف يوم | موقع حقيقي بـ HTTPS وحساب مدير النظام |
| 3. تشغيل تجريبي ثم تعميم | مدرسة أو مدرستان ثم الكل | شهر ثم تعميم | مقارنة مخرجات النظام مع ملفات Excel قبل الاعتماد الكامل |

## الطريقة الأسرع: تجربة أونلاين خلال دقائق (GitHub Codespaces)

بدون خادم أو دومين أو تثبيت أي شيء على جهازك. يعمل النظام في سحابة GitHub ببيانات تجريبية، وتحصل على رابط تفتحه من المتصفح (ويمكن مشاركته مؤقتاً).

1. افتح المستودع على GitHub: `github.com/mohasker/School-Accountant` واختر الفرع `claude/vibrant-bell-tj6ext` (أو `main` بعد الدمج).
2. (اختياري، مستحسن) حدد كلمة مرور التجربة: **Settings ← Secrets and variables ← Codespaces ← New repository secret** باسم `DEMO_PASSWORD` وقيمة 8 أحرف على الأقل. إن لم تحددها تكون كلمة المرور الافتراضية `Madar-Trial-2026`.
3. اضغط الزر الأخضر **Code ← تبويب Codespaces ← Create codespace on …**.
4. انتظر 5–8 دقائق في المرة الأولى (تثبيت وبناء تلقائي). بعدها يفتح النظام في تبويب جديد تلقائياً، أو من تبويب **PORTS** افتح المنفذ **3000**.
5. ادخل بالحساب `accountant` أو `admin` وكلمة مرور التجربة.

**مشاركة الرابط مع زملاء للتجربة:** في تبويب PORTS اضغط يمين على المنفذ 3000 ← **Port Visibility ← Public**، وانسخ الرابط. غيّر كلمة المرور الافتراضية قبل المشاركة.

**ملاحظات:**
- مجاني ضمن حصة GitHub الشهرية (حوالي 60 ساعة تشغيل لجهاز بمعالجين).
- يتوقف الـ Codespace بعد 30 دقيقة دون استخدام، وتبقى البيانات. لإعادته: github.com/codespaces ← افتحه، ويعمل النظام تلقائياً.
- للتجربة فقط؛ لا تُدخل بيانات حقيقية. عند الاعتماد انتقل إلى المرحلة 2 (النشر على خادم بدومين).
- لحذف البيانات التجريبية والبدء من جديد: في الطرفية `rm -rf .data && bash .devcontainer/start.sh`.

## المرحلة 1: التشغيل على جهازك (Windows) — النسخة العادية، الأسهل، بدون GitHub

### مرة واحدة فقط
1. ثبّت **Node.js** (نسخة LTS) من nodejs.org: اختر Windows Installer واضغط Next حتى النهاية.
2. فك ضغط ملف **Madar-V0.zip** في مجلد على جهازك (مثلاً `C:\Madar`).

### التشغيل
- اضغط مرتين على **`Start-Madar.bat`** داخل المجلد.
- أول مرة تستغرق بضع دقائق (تثبيت وتجهيز، تحتاج إنترنت)، وبعدها يفتح النظام خلال ثوانٍ.
- يفتح المتصفح تلقائياً على **http://localhost:3000**. ادخل بحساب مدير النظام وأضف المحاسبين من لوحة مدير النظام، وكل محاسب يضيف مدارسه.

الحسابات الجاهزة (لا يوجد تسجيل من صفحة الدخول؛ الحسابات يُنشئها مدير النظام فقط):

| الحساب | اسم الدخول | كلمة المرور |
|---|---|---|
| مدير النظام | `Admin` | `Admin1122334455` |
| المحاسب (تجريبي) | `accountant` | `Accountant2026` |
| ضيف | `guest` | `Guest2026` |

كلمات المرور هذه **مؤقتة**: عند أول دخول يطلب النظام من كل حساب اختيار كلمة مرور خاصة به قبل أي عمل (وكذلك بعد أي إعادة تعيين من مدير النظام). أوقف حساب الضيف إذا لم تحتجه.

- هذه **النسخة العادية** ببياناتك الحقيقية ولا تحتوي بيانات تجريبية.
- اترك النافذة السوداء مفتوحة أثناء الاستخدام، وأغلقها لإيقاف النظام.
- البيانات تُحفظ في مجلد `.data\moesas` داخل مجلد النظام، وتُؤخذ نسخة يومية تلقائياً في `.data\backups` (آخر 14 يوماً)، ونسخة تلقائية قبل أي مسح من لوحة مدير النظام. من **لوحة مدير النظام ← النسخ الاحتياطية**: «نسخة الآن»، و«استعادة هذه النسخة»، و«مجلد نسخة ثانية» (فلاشة أو مجلد OneDrive على الجهاز) تُنسخ إليه كل نسخة تلقائياً. **لا تحذف مجلد `.data`**.
- عند التحديث لنسخة جديدة: فك الضغط فوق المجلد نفسه (أو انسخ مجلد `.data` إلى المجلد الجديد) حتى تبقى بياناتك.
- المرفقات لا تُفحص بـ ClamAV على جهاز Windows (يُتحقق من نوع الملف فقط، ويفحص برنامج الحماية في الجهاز الملفات).
- **للتجربة**: اضغط مرتين على **`Start-Madar-Trial.bat`** (الدخول `admin` أو `accountant` بكلمة `Madar-Trial-2026`). فيه بيانات من ملفاتك المعتمدة: المدارس التسع، الموردون، 504 شهادات سابقة بموضوعاتها، الشهادات 2022–2026 في سنواتها المالية على بنود الموازنة، سجل المديرين (3 مدارس تغيّر مديرها)، كشف استعاضة النثرية الكامل، والتكليف المفتوح بتاريخ 22 سبتمبر، والإجازات — بالإضافة لمعاملات تجريبية في كل المراحل. تُحفظ في `.data\demo` منفصلة تماماً عن بياناتك الحقيقية؛ لإعادة التجربة من البداية احذف مجلد `.data\demo`. شغّل واحداً فقط من الملفين في نفس الوقت.
- **رفع تعديلاتك على الكود إلى GitHub**: `Upload-To-GitHub.bat` (يحتاج Git for Windows)؛ يرفع على فرع جديد للمراجعة ولا يرفع البيانات أبداً. التفاصيل في دليل الاستخدام.
- تصدير PDF يستخدم متصفح Edge أو Chrome الموجود على الجهاز، وخطوط Calibri وArial الأصلية في Windows.

| الحساب | جرّب به |
|---|---|
| `accountant` | المحاسب: كل خطوات المعاملة (تقرير العروض، التكليف، الشهادة والتغطية)، العهد، الإعدادات والإجازات |
| `admin` | مدير النظام: كامل الصلاحيات، تقارير الحسابات، السياسة المالية ودليل البنود، مسح البيانات |
| `other` | محاسب مدرسة أخرى للتأكد أنه لا يرى بيانات مدارس غيره |


### سيناريو تجربة مقترح (قائمة تحقق)
- [ ] `admin`: أضف إجازات العام الحالي، وراجع **السياسة المالية** (1000 / 3 عروض / 200,000 / 1% / 10% / 75%).
- [ ] `accountant`: راجع الشاشة الرئيسية وغيّر الفترة، ثم افتح المعاملات الجاهزة في كل مرحلة.
- [ ] معاملة جديدة بعروض ثلاث شركات (اكتب اسم شركة جديدة في أحدها) ← إصدار تقرير العروض ← التكليف بمدة أيام عمل.
- [ ] جرّب عرضاً واحداً فوق 1000 (يُرفض إلا بمبرر احتكار).
- [ ] «إصدار شهادة الإنجاز وكتاب التغطية» بتاريخ إنجاز متأخر، وتحقق من أيام التأخير والغرامة، ونزّل **PDF** للمستندات الأربعة.
- [ ] العهد: افتح نثرية بقيمة، سجّل فواتير حتى 75%، ثم «تسوية / استعاضة» واطبع الكشف وكتاب التغطية؛ جرّب فاتورة كتب على حساب الأصل 110805.
- [ ] قارن كل نموذج PDF مع ملف Excel المعتمد (الأرقام، التفقيط، الصياغة، التوقيعات).
- [ ] `admin`: افتح **تقرير الأعمال** لكل حساب، وجرّب إعادة تعيين كلمة مرور وإيقاف حساب.

دوّن أي ملاحظة على الصياغة أو الحسابات لتعديلها قبل النشر.

## المرحلة 2: النشر على خادم سحابي بدومين خاص

### ما تحتاجه
| البند | المقترح |
|---|---|
| خادم (VPS) | Ubuntu 24.04، **2 معالج و4 GB ذاكرة** على الأقل (فحص الفيروسات وتصدير PDF يحتاجان ذاكرة)، قرص 40 GB. أي مزود مناسب (مثل Hetzner أو DigitalOcean أو AWS Lightsail أو مزود محلي في قطر). يُفضّل موقع البيانات قريباً وضمن سياسة جهتك. |
| دومين (اختياري) | مثل `madar-school.com`. بدونه يحصل الخادم على عنوان مجاني `IP.sslip.io` بـ HTTPS. |
| سجل DNS | عند استخدام دومينك: سجل **A** يوجّه الدومين إلى عنوان IP الخادم. |

### التثبيت بأمر واحد (الأسهل)
1. أنشئ الخادم من لوحة المزود (Ubuntu 24.04) واحصل على عنوان IP وكلمة مرور root.
2. افتح نافذة الأوامر على جهازك (PowerShell في Windows) واتصل بالخادم:
   ```powershell
   ssh root@عنوان-IP
   ```
3. الصق هذا الأمر:
   ```bash
   curl -fsSL https://raw.githubusercontent.com/mohasker/School-Accountant/main/deploy/install.sh | bash
   ```
4. أجب عن الأسئلة: الدومين (أو اتركه فارغاً)، اسم دخول مدير النظام، اسمه، كلمة المرور.
5. بعد 5–10 دقائق يظهر الرابط: **✅ MOESAS يعمل: https://…**

السكربت يثبّت Docker، ويولّد كلمة مرور قاعدة البيانات، ويشغّل النظام بـ HTTPS، وينشئ مدير النظام ودليل البنود، ويجدول **نسخة احتياطية يومية** في `/var/backups/madar` (آخر 30 يوماً). **للتحديث لاحقاً:** أعد تشغيل نفس الأمر (يأخذ نسخة احتياطية أولاً ولا يمس البيانات).

### خيار مجاني: Oracle Cloud (Always Free)
خادم ARM مجاني دائماً حتى 4 معالجات و24 GB ذاكرة، ومنه مواقع قريبة (دبي، جدة، أبوظبي). مناسب للتجربة؛ للبيانات الحقيقية يُفضّل خادم مدفوع.
1. سجّل في oracle.com/cloud/free (يطلب بطاقة للتحقق فقط).
2. **Compute ← Instances ← Create**: الصورة Ubuntu 24.04، الشكل **VM.Standard.A1.Flex** (2 OCPU و12 GB)، ونزّل مفتاح SSH الذي يعطيك إياه.
3. **Networking ← الشبكة ← Security List ← Add Ingress Rules**: المصدر `0.0.0.0/0` والمنافذ `80,443`.
4. اتصل: `ssh -i المفتاح.key ubuntu@IP` ثم شغّل أمر التثبيت مع `sudo`:
   ```bash
   curl -fsSL https://raw.githubusercontent.com/mohasker/School-Accountant/main/deploy/install.sh | sudo bash
   ```
ملاحظات: أحياناً تظهر رسالة «Out of capacity» فجرّب لاحقاً أو منطقة أخرى، وقد توقف Oracle الخوادم المجانية الخاملة طويلاً.

### الخطوات اليدوية (بديل للسكربت)

**1. تثبيت Docker وGit:**
```bash
sudo apt update && sudo apt install -y git ca-certificates curl
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER   # ثم اخرج وادخل مجدداً
```

**2. جلب النظام:**
```bash
git clone https://github.com/mohasker/School-Accountant.git
cd School-Accountant
git checkout main   # بعد دمج طلب الدمج
```

**3. ملف الإعدادات:**
```bash
cp .env.example .env
nano .env
```
اضبط القيم التالية (بقية القيم تُترك كما هي):

| المتغير | القيمة |
|---|---|
| `DOMAIN` | الدومين بدون https، مثل `madar-school.com` |
| `DB_PASSWORD` | كلمة مرور طويلة **حروف وأرقام فقط** (30 حرفاً مثلاً) |
| `ADMIN_USERNAME` | اسم دخول مدير النظام بالإنجليزية، مثل `asker` |
| `ADMIN_NAME` | الاسم الظاهر، مثل `محمد عبد اللاه عسكر` |
| `ADMIN_PASSWORD` | كلمة مرور قوية، 8 أحرف على الأقل |
| `TENANT_NAME` | اسم الجهة الظاهر، مثل `MOESAS` |
| `ANTHROPIC_API_KEY` | (اختياري) مفتاح المساعد الذكي؛ أو يضعه مسؤول النظام من شاشة السياسة المالية |
| `SECRETS_KEY` | مفتاح تشفير الأسرار المحفوظة (سر ربط OneDrive ومفتاح المساعد)، 16 حرفاً فأكثر. يولّده `install.sh` تلقائياً؛ **إلزامي في الإنتاج ولا يُغيَّر بعد الحفظ** وإلا وجب إعادة إدخال الأسرار. احتفظ بنسخة منه مع النسخ الاحتياطي |
| `DEMO_MODE` | `false` |
| `DEMO_PASSWORD` | اتركه فارغاً |

**4. التشغيل:**
```bash
docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml up --build -d
```
البناء الأول يستغرق 5–10 دقائق. يصدر Caddy شهادة HTTPS تلقائياً عند توجيه الدومين للخادم (المنفذان 80 و443 مفتوحان).

**5. إنشاء مدير النظام ودليل البنود (مرة واحدة):**
```bash
docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml run --rm api npm run bootstrap
```
بعدها احذف `ADMIN_PASSWORD` من ملف `.env` لأنه لم يعد مطلوباً.

**6. افتح `https://الدومين`** وادخل بحساب مدير النظام.

### الإعداد الأول داخل النظام (مدير النظام)
1. **الإجازات الرسمية**: أدخل إجازات العام كاملة.
2. **السياسة المالية**: راجع القيم.
3. **الإعدادات ← دليل بنود الموازنة**: راجع البنود وأرقام الحسابات (منها المكتبة 510201 / أصل 110805، ومواد مسار مهني 10001).
4. **الإعدادات ← المدارس**: أضف كل مدرسة (الاسم، المدير، مسؤول النثرية، رمز أوامر الشراء).
5. **إسناد مستخدم**: أنشئ حساب المحاسب ومعتمد كل مدرسة، وسلّم كلمات المرور بطريقة آمنة (يغيّرها المستخدم من «أمان حسابك»).
6. لكل مدرسة: **الموازنة ← إضافة البنود الرسمية** ثم اعتماد المبالغ.
7. **الموردون**: أدخلهم أو استوردهم CSV (`samples/suppliers.csv`).

### النسخ الاحتياطي (إلزامي)
نسخة يومية تلقائية للقاعدة (تشمل المرفقات والمستندات):
```bash
mkdir -p ~/backups
crontab -e
# أضف السطر:
0 2 * * * cd ~/School-Accountant && docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml exec -T db pg_dump -U school -Fc school_accounting > ~/backups/madar-$(date +\%F).backup
```
انسخ الملفات دورياً إلى مكان آخر خارج الخادم (مشفرة)، وجرّب الاستعادة مرة على قاعدة جديدة (`docs/security-and-operations.md`).

### التحديث عند صدور نسخة جديدة
```bash
cd ~/School-Accountant
docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml exec -T db pg_dump -U school -Fc school_accounting > ~/backups/before-update.backup
git pull
docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml up --build -d
```
الترحيلات تُطبق تلقائياً عند التشغيل.

### أوامر مفيدة
| الغرض | الأمر |
|---|---|
| حالة الخدمات | `docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml ps` |
| سجل الأخطاء | `... logs -f api` أو `... logs -f web` |
| إعادة التشغيل | `... restart` |

## المرحلة 3: التشغيل التجريبي ثم التعميم
1. **شهر تجريبي** على مدرسة أو مدرستين بالتوازي مع ملفات Excel: كل معاملة تُسجل في النظام وتُقارن مخرجاتها (التكليف، الشهادة، الغرامة، كشف النثرية) مع Excel.
2. اجمع الملاحظات وأرسلها لتعديلها.
3. بعد التطابق: أضف بقية المدارس (حتى 75)، ودرّب المحاسبين على `docs/user-guide-ar.md`.
4. راجع **لوحة مدير النظام** أسبوعياً: المعاملات قيد الإعداد، التأخيرات، وتنبيهات الاستعاضة.

## عند حدوث مشكلة
- الموقع لا يفتح: تأكد من سجل DNS ومن فتح المنفذين 80 و443، ثم راجع `logs -f proxy`.
- رفع المرفقات يفشل: راجع `logs -f api`؛ غالباً تحديث تواقيع ClamAV (`docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml exec -u root api freshclam`) أو نقص الذاكرة.
- نسيان كلمة مرور مستخدم: مدير النظام ← كلمة المرور. نسيان كلمة مرور مدير النظام نفسه: أنشئ مديراً آخر بعد التواصل مع من أعدّ النظام.
