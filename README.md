# مَدار — المساعد المحاسبي للمدارس الحكومية

نسخة تجريبية تنفيذية **0.2.0**، وليست اعتماداً للاستخدام المالي الرسمي.

## ما يعمل

- واجهة عربية RTL: لوحة التحكم، المعاملات، الموردون، الموازنة، العهد، التقارير، الإعدادات، سجل التدقيق.
- جلسات خادمية قابلة للإلغاء، CSRF، تحديد محاولات الدخول، وصلاحيات مستقلة لكل مدرسة.
- إضافة الموردين وتعديلهم واستيراد CSV؛ حذف غير المستخدم، وتعطيل المورد المرتبط بمعاملات.
- دورة المنافسة والتكليف الوزاري المباشر، الأصناف، التوريد الجزئي، الشهادات الجزئية والنهائية والتغطيات.
- غرامة 1% يومياً من قيمة الجزء المتأخر بسقف تراكمي 10% من التكليف؛ الخصم السابق لا يُكرر.
- مراجعة المستندات المؤيدة، وربط النسخ الموقعة بكل شهادة وتغطيتها قبل اكتمال الملف.
- ارتباطات ومصروفات الموازنة بمعاملات ذرية، ومنع تجاوز الرصيد.
- العهد والمصروفات والتسويات والاستعاضة الفعلية وإثبات إعادة الرصيد.
- تسجيل ERP **يدوي موثق**، وليس تكاملاً مع خادم الوزارة.
- تقارير معاملات مخصصة/شهرية/سنوية محفوظة، إعادة طباعة، CSV وExcel، وحفظ PDF من الطباعة.

## تشغيل سريع للتجربة — Node.js 24

من مجلد المشروع:

```bash
npm ci
npm run build
```

أول تشغيل في PowerShell على Windows:

```powershell
$env:DEMO_PASSWORD="ضع-كلمة-مرور-قوية-للتجربة"
npm run demo
```

على macOS/Linux:

```bash
DEMO_PASSWORD='ضع-كلمة-مرور-قوية-للتجربة' npm run demo
```

افتح `http://localhost:3000`. الحسابات: `accountant`، `approver`، `admin`، `other`.
كلمة المرور هي القيمة التي حددتها أنت، وليست كلمة سر ثابتة مضمنة في التطبيق.

| الحساب | الاستخدام |
|---|---|
| accountant | محاسب المدرسة الأولى، إنشاء المعاملات والتوريدات والمرفقات |
| approver | مراجع/معتمد المدرسة الأولى ومسجل ERP في بيانات الاختبار |
| admin | إعدادات ومستخدمو المدرستين، دون صلاحية مالية تلقائية |
| other | محاسب المدرسة الثانية لا يستطيع الوصول إلى الأولى |

`npm run demo` يشغل PGlite وAPI وNext.js في عملية تشغيل مترابطة، ويحفظ البيانات تحت `.data/demo`.
يتحقق من بصمة الترحيلات ولا يعيد تهيئة قاعدة تحتوي على بيانات. إعادة التشغيل لا تغير كلمات المرور القائمة.
PGlite قاعدة تطوير محلية وليست بديلاً عن اختبار PostgreSQL متعدد الاتصالات قبل الإنتاج.

## تشغيل Docker مع PostgreSQL خادمي

أنشئ `.env` يحتوي `DB_PASSWORD` قوية و`DEMO_PASSWORD` قوية و`DEMO_MODE=true` و`NODE_ENV=development` للتجربة المحلية فقط.
استخدم كلمة DB_PASSWORD أبجدية رقمية طويلة لتجنب ترميز المحارف الخاصة في رابط الاتصال.

```bash
docker compose up --build -d
docker compose run --rm api npm run seed
```

يعمل seed على قاعدة فارغة فقط. فتح الموقع على `http://localhost:3000`.
لا تنفذ seed على قاعدة حقيقية. لا تنشر هذه الإعدادات التجريبية للعموم.

لم يكن Docker متاحاً في بيئة إعداد هذه الحزمة؛ ملفاته جاهزة للمراجعة والتشغيل المحلي، ولم يُدّعَ أن صورها بُنيت هنا.

## الاختبارات

```bash
npm run typecheck
npm test
npm run build
```

الاختبارات تنشئ PostgreSQL/PGlite في الذاكرة وتستخدم HTTP فعلياً، ولا تحذف قاعدة بيانات المستخدم.
راجع `docs/test-results.txt` و`docs/release-readiness.md` لمعرفة ما اختُبر وما لم يُختبر.

## نموذج استيراد الموردين

ملف UTF-8 CSV برؤوس `name,cr,phone,email`، مثال في `samples/suppliers.csv`.
الاستيراد ذري: يفشل بالكامل عند وجود تكرار أو خطأ. لا يُستبدل مورد موجود صامتاً.
تُدخل بنود الموازنة يدوياً في هذه النسخة. القائمة الرسمية والنماذج والشعار لم تُرفق بعد.

## بنية المشروع

- `apps/api/src`: API، الجلسات، الصلاحيات، قواعد المال والمستندات.
- `apps/web/app`: واجهة Next.js عربية، ووكيل API من نفس المصدر.
- `prisma`: المخطط والترحيلات والقيود المالية وسجل التاريخ غير القابل للتعديل عبر SQL المعتاد.
- `tests`: حسابات وصلاحيات ودورة كاملة وقيود البيانات.
- `scripts`: بيانات اختبار وتشغيل محلي.
- `docs`: دليل المستخدم، الحدود وخطة الاعتماد.

**مهم:** لا تُزل بوابة الاعتماد في إصدار الشهادات لمجرد تغيير `DEMO_MODE`. جميع المخرجات تحمل عبارة تجربة. يلزم إدماج النماذج الرسمية والموافقة المؤسسية ومراجعة أمنية قبل اعتماد الاستخدام الحقيقي.
